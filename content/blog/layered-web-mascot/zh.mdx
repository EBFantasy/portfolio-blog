页面左下角的看板娘不是视频，也没有套用骨骼动画框架。她来自一张经过 PSD 手工分层的立绘：保留原图的头发、眉毛和手指，只把需要相对运动的眼部拆开。所谓 Web 2.5D，在这里不是三维计算，而是用正确的遮挡关系、很小的虹膜位移和短暂闭眼，让静态画面产生可被感知的纵深。

## 先确定层序，再谈动画

所有部件都放在同一个 `700 / 997` 比例容器中，以百分比记录位置和尺寸。层序从低到高是：

1. **base**：完整底图，但眼区被挖空并回填周围皮肤，避免底层残留固定眼球。
2. **wall**：左右眼白与眼角内壁，垫在虹膜下面。
3. **iris**：左右虹膜，是唯一直接随光标平移的眼部部件。
4. **lash**：睫毛与眼线框，压在虹膜上，恢复眼睛原有的线条。
5. **lid**：闭眼件，只在眨眼时显示，覆盖睁眼状态下的 wall、iris 和 lash。

这个顺序意味着眨眼不需要重算一张新图。闭眼时隐藏睁眼部件，显示最高层 lid；约 160 毫秒后再切回去。本体不跟随光标转动，点击只弹出台词气泡，轻微呼吸浮动与眼部交互分开处理。

**wall 尤其不能烘焙进第二只眼睛。**如果眼白层里还留着原图虹膜，活动 iris 一旦移开中心，下面那只静态虹膜就会从边缘露出来，形成双瞳孔或重影。wall 只能保留眼白和眼窝内壁；所有需要移动的深色瞳孔、虹膜高光，都只能存在于 iris 层。底图眼区挖空也是同一个原因。

## 遮罩固定，虹膜在窗口内移动

眼球随动不是把整张眼睛拖向光标。socket 窗口与遮罩始终固定，只有窗口内的 iris 发生位移。这样即使虹膜移动，也会继续被手工裁出的眼窝轮廓限制，不会滑到皮肤或眼线之外。

当前实现以立绘容器估计眼部中心，把光标向量转成方向，再用距离控制位移幅度：

```ts
const dx = e.clientX - eyeCenterX;
const dy = e.clientY - eyeCenterY;
const dist = Math.hypot(dx, dy);
const angle = Math.atan2(dy, dx);
const factor = dist > 0 ? Math.min(dist / 350, 1) : 0;

setEyeOffset({
  x: Math.cos(angle) * 5.5 * factor,
  y: Math.sin(angle) * 5.5 * factor,
});
```

最大位移只有 `5.5px`。这个限制很重要：看板娘只需要传达「注意到了光标」，不需要让眼睛追着指针满屏移动。虹膜变换带有很短的 ease-out，遮罩则同时设置 `maskImage` 与 `WebkitMaskImage`，尺寸拉满固定窗口。

## 切件缓存需要同一个版本号

底图、眼白、虹膜、睫毛、闭眼件和遮罩是彼此依赖的一组资源。当前公共图片 URL 统一携带 `?v=8`，例如 `/oc_iris_l.png?v=8`。查询串提供了一个可手动推进的缓存版本：修改切件后同步递增整组版本，可以降低新虹膜配旧遮罩、左右眼来自不同批次的风险。

版本号不能替代正确的缓存响应头，也不会自动发现文件变化；它只是发布时明确换 URL 的约定。因此，几何参数、遮罩和图片若属于同一次调整，也应作为一组一起检查，而不是只替换其中一张图。

## 减少动态效果仍是明确缺口

当前组件还没有读取 `prefers-reduced-motion`，所以不能把它写成已经支持。正确的接入方式不只是缩短 CSS 动画：当用户要求减少动态效果时，应保留静态角色和点击台词，停止呼吸浮动、自动眨眼与光标跟随；偏好发生变化时也要重新判断。CSS 至少可以先撤掉循环动画与位移过渡：

```css
@media (prefers-reduced-motion: reduce) {
  .mascot-body { animation: none; }
  .iris { transition: none; }
}
```

JavaScript 还应在注册 `mousemove` 和眨眼定时器之前检查同一媒体查询，否则视觉过渡消失，状态仍会不停更新。分层让这些小范围控制成为可能：不必摧毁整张立绘，只需让运动层安静下来。
