你好，欢迎来到 EBFantasy。这个站点用来存放可以亲手操作的网页实验，也记录实现它们时遇到的具体问题。与其把第一篇文章留给排版测试，不如先说明这里有什么、哪些是模拟，以及写作会遵循什么边界。

## 六个可以亲手操作的 Demo

作品区目前收录六个 Demo。它们展示交互流程与工程思路，但不都被包装成完整产品：

1. **爬虫调度可视化**：在固定的 24 页模拟站点图上执行广度优先遍历，可以调整并发与抓取间隔，观察链接去重、robots 拦截和模拟 429 重新排队。
2. **电商价格监控**：用模拟价格流驱动 SVG 折线、区间统计与阈值告警，也可以主动触发一次促销跳水，检查告警链路如何响应。
3. **多表报表流水线**：以三份内置区域样例展示校验、清洗、去重、合并、汇总五个阶段，并在浏览器中生成可下载的 CSV。它演示处理流程，不代表已经读取或清洗了访客上传的文件。
4. **茶时点单**：在浏览器内完成茶饮规格选择、实时计价、购物车、下单与出餐进度体验；支付和订单状态属于演示，不会形成真实交易。
5. **星幕影院选座**：操作可缩放的座位图，查看可售、已售、锁定与选中状态，体验连座检测、分区计价和模拟结算。
6. **订阅付费计划**：切换月付与年付、比较方案功能并走完结账界面。这里展示计费交互，不保存真实支付信息，也不创建真实订阅。

这些页面的价值在于把状态变化摊开给人看。模拟数据并不丢人，前提是明确标注；Demo 也不应被描述为真实客户系统或生产环境集成。

## 六套概念 UI，不是客户案例

模板画廊与作品区分开。Apex 策略咨询、翠庭法式餐厅、Nexus AI 数据平台、Pulse 行为分析、星坠战纪和霓虹街机，分别用来练习商务、科技与游戏三类主页的不同视觉语言：克制的编辑排版、餐饮品牌的暖色质感、深色数据界面，以及更强调氛围的游戏视觉。

六套页面中的品牌都是明确虚构的。宣传数字、人物引语、公司历史和业务承诺同样只是版式内容，用来检验信息层级与组件密度，不能当作真实客户、真实产品或实际业绩。它们回答的是「这种界面可以怎样组织」，而不是「谁已经购买了它」。

## 技术栈与双语内容管道

站点使用 **Next.js 15、TypeScript 与 Tailwind CSS v4**。App Router 按目录组织路由，`next/image` 负责图片组件，交互 Demo 则由客户端组件承载。文章不是存放在数据库里，而是本地 MDX：目录名作为 slug，`zh.mdx` 与 `en.mdx` 分别承载两种语言。

服务端用 `gray-matter` 读取 frontmatter，再经 `remark-parse`、GFM 和 `rehype` 转为 HTML。最小元数据约定如下：

```yaml
---
title: "文章标题"
date: "2026-10-07"
lang: "zh"
summary: "列表页使用的简短说明"
tags: ["Next.js", "建站"]
---
```

`title` 与 `date` 是文章进入列表的必要字段；缺少它们时，解析器会跳过该文件。标签保持简短，摘要只交代文章实际讨论的内容。

## 当前写作方向

目前的写作集中在三类问题：PSD 分层素材如何变成可维护的 Web 动效，定时器与状态机如何共同支撑可暂停、可重置的 Demo，以及模拟能力和真实能力如何在文案中划清界限。也会记录资源缓存、CSV 导出和减少动态效果偏好这类容易被演示效果掩盖的细节。

中文稿会先完整成稿，再翻译成对应英文，而不是逐句替换关键词。这里不把计划写成成绩，不把概念页面包装成上线项目；尚未接入的改进会明确称为方案或缺口。希望每篇文章都能让读者带走一个可复用的判断，而不只是浏览一次效果。
